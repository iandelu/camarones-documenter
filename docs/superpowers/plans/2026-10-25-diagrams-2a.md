# Diagrams from the code (delivery 2a, no AI) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install and `camaron diagrams` draw four Mermaid diagram kinds from the code (states, endpoints map, context
map, messaging) as generated blocks that can be confirmed and protected, shown with a badge in the portal, and taught
to agents by a new `cam-docs-diagrams` skill.

**Architecture:** New `lib/diagrams.py` scans and renders the four kinds; `lib/genblocks.py` gains optional block
attributes (`id`, `confirmed`, `by`), two states (`confirmed`, `confirmed-stale`) and delegates the new kinds to
`diagrams`. Pages `architecture/system-map.md` and `repos/<repo>/diagrams.md` are written at install and refreshed.
The portal reads block markers (and their states from `/api/doc`) to show a badge.

**Tech Stack:** Python 3.10+ (pytest via `uv`), React content helpers + Vitest, legacy portal scripts.

**Spec:** `docs/superpowers/specs/2026-10-25-diagrams-design.md` — this plan implements its §10 delivery **2a**:
§2, the `confirmed`/`confirmed-stale` states and `check` warning of §4, the badges of §6, and §7.

Work in the worktree `.claude/worktrees/diagrams` (branch `worktree-diagrams`, from local main `b6d694e`).

## Global Constraints

- macOS, Windows, Linux: `pathlib`, `encoding="utf-8"`, `newline="\n"` on writes; no OS-specific code.
- Block syntax stays backward compatible: `<!-- generated:<kind> repo=<repo> sha=<hash> -->` without the new
  attributes reads and refreshes exactly as before.
- New attributes, in this order when present: `repo=… id=… confirmed=… by=… sha=…`.
- `repo=_system` is reserved for system-wide blocks; it never appears in `docs.repo_names()`.
- Ruling on spec §2 "ORM enums from `schemas.py`": `schemas.py` reads no enums; JPA/ORM status fields are typed
  by language enums, which Task 2 already scans. No ORM-specific scanner.
- Every diagram ≤ 25 nodes (spec §2); labels with Mermaid-special characters are quoted; node ids via
  `quickarch.ident`.
- States diagrams never contain a transition; they carry `note right of <first state> : transitions: waiting for a proposal`.
- `refresh` never rewrites a block with `confirmed=`, with or without `force`.
- Pages a person owns (`x-owner: human`) are never written.
- User strings in `en` and `es`. Kit version: next minor of main at merge time (4.50.0 against today's 4.49.0).

## Review Focus

1. An agent moved a generated block from `repos/api/diagrams.md` to `flows/checkout.md`: a later `camaron diagrams`
   must not write it back into `diagrams.md` (no duplicate) — Task 5 `test_a_moved_block_is_not_written_twice`.
2. An enum is deleted from the code: its unconfirmed block leaves the generated page; a confirmed one stays and is
   reported `confirmed-stale` — Task 5 `test_a_gone_enum_leaves_the_page_unless_confirmed`.
3. A repo with no endpoints, enums or topics gets no empty `diagrams.md` — Task 5 `test_no_page_without_diagrams`.
4. Labels with quotes, brackets, `{id}` path params or spaces render as valid Mermaid — Task 3
   `test_path_params_and_special_labels_are_quoted`.
5. The static export (no `/api/doc` states) still shows "From the code" / "Confirmed by …" from the markers alone —
   Task 6 vitest `badge comes from the marker when no state is given`.
