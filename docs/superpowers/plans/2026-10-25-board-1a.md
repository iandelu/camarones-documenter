# Board (Tablero) — delivery 1a Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Backlog.md-compatible Kanban in `cam-docs/backlog/`, with no AI: items linked to doc pages, an
authoritative `board.yaml` with a per-card git merge driver and a repair pass, a `camaron board` CLI and a portal
Kanban that writes only with the machine's token.

**Architecture:** A new package `lib/kanban/` holds pure parts (item format, `board.yaml`, ordinals, merge, x-id
links) and the operations that write files under one cross-process lock. The CLI, the portal server and the
checkpoint/share flow all call `kanban.ops`/`kanban.repair`; the portal gets a React view (`Kanban.jsx`) over pure
helpers (`kanban.js`).

**Tech Stack:** Python 3 stdlib + PyYAML (already a kit dependency), git merge drivers, React 19 + Vite + vitest
(the existing portal app). No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-24-board-design.md` (requirements:
`docs/research/dev-harness-requirements.md`). Read both before starting.

**Not committed yet:** the spec, the requirements, the gap analysis and this plan are uncommitted on purpose (user
instruction). Implementation commits stage only the files each task lists, never `docs/research/*` or
`docs/superpowers/*`, unless the user says so.

## Global Constraints

- macOS, Windows and Linux: `pathlib` only, `encoding="utf-8"`, LF (`newline="\n"`) on every file the kit writes,
  processes through `lib/common.py` helpers (`run`, `out`, `which`), `IS_WIN`/`IS_MAC` only (AGENTS.md 2.1).
- TDD: the failing test first; tests offline with `make_workspace`/`isolated_env`/`kit`/`wired`; network only under
  `tests/e2e/` with the `e2e` marker (AGENTS.md 2.2).
- Backward compatible: a 3.x/4.x project without `backlog/` behaves exactly as before until `board init`; new
  `workspace.yaml` keys only, all optional: `board: {archive_after_days, definition_of_done}` (spec §10).
- Backlog.md target format **v1.55.3**: `VERSIONS["backlog_md"] = "1.55.3"`; field names, section headers and
  markers unchanged; our additions are `x-` fields only (spec §2.2).
- Statuses, fixed, in files always in English: `Backlog, Ready, In Progress, In Review, Done, Blocked`; es UI labels:
  `Backlog, Listo, En curso, En revisión, Hecho, Bloqueado` (spec §2.1).
- Types `[epic, story, bug, spike, task]`; priorities `[P0, P1, P2, P3]`; `task_prefix: "WI"`; draft prefix `draft`.
- Ordinal step `1000` (spec §2.3); archive after `14` days by default (spec §4).
- Default DoD (en): "acceptance criteria met", "linked docs updated and confirmed", "PR reviewed"; es: "criterios de
  aceptación cumplidos", "docs enlazadas actualizadas y confirmadas", "PR revisada".
- Voice (AGENTS.md §3): at most one shrimp joke, only on success/empty states; none in errors, warnings, `--json`.
  CLI messages follow the surrounding CLI (English); portal strings exist in `es` and `en`.
- Kit-internal names say `kanban`; UI says Tablero/Board; the whiteboards keep their code (`boards.py`,
  `Boards.jsx`, `#/boards`) and only their English label becomes "Whiteboards" (es already "Pizarras").
- Commits: conventional (`feat(board): …`), stage only your own hunks (parallel sessions edit this tree).

## Review Focus

1. **Titles a filesystem rejects** — `<>:"/\|?*`, a trailing dot/space, emoji, 300 characters: the file name must be
   valid on Windows and capped (60 chars for the title part), the frontmatter keeps the full title. Test in Task 1.
2. **A hand-broken item file** (bad YAML, missing `id`, CRLF line endings from a Windows checkout): `board list`
   and the portal still load every other item and report the broken one by path; CRLF parses like LF. Test in Task 1
   and Task 5.
3. **Two writers at once** (portal tab + CLI, or two tabs): no lost card, no torn `board.yaml`. Test in Task 4.
4. **Spaces in the kit or uv path** (Windows `C:\Users\Ana María\…`): the merge driver command is quoted and runs
   through git's `sh` on every OS. Test in Task 3.
5. **Linking a page that has no frontmatter, or a confirmed page whose frontmatter has comments**: x-id is inserted
   without touching the body or rewriting other frontmatter lines; trust stays `confirmed`. Test in Task 6.
