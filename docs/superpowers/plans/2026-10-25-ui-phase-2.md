# UI redesign, phase 2: the desktop app with its own renderer — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The desktop app stops being "the portal plus a Taller" and gets its own UI for operating projects: a project
rail, the project's sections (Summary, Plan, Interviews, Team, Quality, Docs) and machine sections (Machine, Kit dev),
a jobs panel and a status bar. The portal (phase 1) stays the reader, in the browser and in the app's Docs.

**Architecture:**

- `.camarones/desktop/renderer/`: React + Vite, the same `@camaron/ui` kit and theme as the portal; built into
  `desktop/renderer-build/` (committed, checked in CI like `portal/app-build/`).
- **Same origin, no CORS:** a project window loads the renderer from that project's own server
  (`lib/serve.py` serves it at `/desktop/`, static like the portal: a page load carries no custom header, and the
  build is the kit's public code; the API behind it still wants the app token), so the API calls are the same as
  today and the token stays the only key. Without a project open, the main process loads the same build from disk in
  hub mode (`window.camaronHub`, no API).
- **One window, a project rail:** picking another project in the rail asks the main process to start that project's
  server and load it in the same window (new IPC `app:projects`, `app:switch`); the previous server stops.
- The Taller's panels and the Pipeline are reused from the portal's sources at first (Vite alias); they move into
  `desktop/renderer/` as each section is rebuilt task-first, and the portal drops the Taller zone at the end.
- Docs: the portal of the same server, in a second window (or the browser), so the reader is not duplicated.

**Coordination:** another session has uncommitted changes in `desktop/main.cjs`, `preload.cjs`, `lib/core.cjs` and the
hub (the header as the title bar, the app menu button). This phase builds in new files first and touches those
files last, with additive hunks; it ports the title-bar behaviour once that work is on `main`.

## Tasks (one commit each)

1. **Skeleton.** `desktop/renderer/` (package.json pinned, vite config with the `@camaron/ui` alias and theme
   plugin, Vitest), the app shell (rail, project sidebar, content, jobs panel, status bar) with hub mode and project
   mode, built into `renderer-build/`. `serve.py` serves `/desktop/` (pytest). Kit dev's
   `desktop-test` and CI run `node --test "test/*.test.cjs"` (the renderer's tests are Vitest's). CI builds and diffs
   it. No user-visible change yet.
2. **Switch the windows.** `main.cjs` loads `${origin}/desktop/` for a project and the build from disk for the hub;
   `app:projects` / `app:switch`; window size and position remembered. `core.cjs` helpers tested with `node --test`.
3. **Summary** with the next step (from the plan and the doctor), and the jobs store (jobs survive view changes).
4. **Plan, Interviews, Team** sections (Pipeline, interview export/import, sync), task-first; "All commands" folded.
5. **Quality** (doctor cached with "Check again", context, golden questions, A/B) and **Machine** / **Kit dev**.
6. **Retire the portal's Taller** (the zone, AppOnly notes) and the old hub; README, tutorial, version.
