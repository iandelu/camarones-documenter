| `34b22a7` (ADR fix, this note) | cancelled | The same hang |
| `9d56d50` (S2, ADRs) | cancelled | GitHub's 6-hour job limit cut the same hang |
| `e76c06b`, `ef6d25e` | failed | Windows: `/api/tree` timeouts and a scheduler timing assert, both fixed by PR #3 |

What PR #3 found, in short. Its description has the evidence and what is still inference.

- **The hang was a kit bug.** On Windows, creating a ConPTY left the server's stdin on a console, so a later child's
  `input()` waited for someone to type: `test_cli_docs_reset` never returned. A person hit it too: after the first
  terminal on the canvas, a project server's children inherited that console. The std handles now go back once the
  terminal's program has started.
- **Page loads waited for npm, on every OS.** Each `/api/tree` ran `npm ls -g` up to six times when OpenWiki was
  missing. The version is now read from the `package.json` behind the command.
- **The scheduler test** no longer depends on how fast `git worktree add` is.
- **A hung test ends the run.** Past 10 minutes a test dumps every thread's stack and fails by name
  (`tests/fixtures/hang_watchdog.py`), a crashed worker ends the run (`--max-worker-restart=0`), and the job has a
  60-minute limit.

Some tests can still fail locally under heavy load and pass when run alone:
`test_locks.py::test_two_processes_writing_the_plan_lose_nothing`, and, in one run at a load average of 64 to 160,
tests in `test_portal_actions.py` and `test_portal_kanban.py`.

## Known issues left on purpose

The final reviews passed these changes as ready to merge, and these were deferred. None blocks anything. Paths are under
`.camarones/` unless they start with `tests/`, and line numbers for the two slices are for `9d56d50`.

**Pair canvas S2**

- `desktop/renderer/src/terminals.js` `shown()`: removing a unit's newer failed terminal brings back its older failed
  one, with a blank screen after a remount. The comment there says an older one never comes back.
- `lib/agents.py:159`: a window that fails to open leaves its unit refused for 30 s as "already open in a window". End
  the record when the open fails.
- Accepted cost: a remount within 2 s of a terminal query answers that query twice.
- The server handles SIGTERM but not SIGHUP on POSIX, and `select.select` has the `FD_SETSIZE` ceiling.

**Dynamic ADRs S1**

- `lib/adr_doc.py` `_status_line` and `_inline` read an inline `status:` outside the preamble, including in fenced YAML.
  Only legacy ADRs with an unknown status reach this.
- `lib/adr_doc.py:52` `_SKELETON_RE` (and its JS mirror) also matches `<https://…>` and `<br>`, so a link-only
  *Considered options* is replaced on accept.
- The English CLI message names the Spanish labels ("Decisiones › Revisar en sesión").
- `_affected` skips wiki pages and `covering` does not, so a wiki page can show the banner without being in *Docu
  afectada*.
- Kit-wide: pages that are symlinks pointing outside `docs/` are still read (writes are refused).
- `adr.py` (about 740 lines) and `Review.jsx` should be split at the next change.

**Setup state and Kit files repair (PR #4)**

- The terminal wizard's setup paths do not call `mark_setup`; only `lib/onboard.py` does.
- The guided tour does not mention where sessions open.

**Windows CI (PR #3)**

- The `sse` helper in `tests/test_terminals_api.py` has no overall deadline. The stream sends a keep-alive every 15 s,
  so its socket timeout never fires and only the 10-minute watchdog stops it.
- `tests/test_docs_reset.py` is deliberately unchanged, so a future console stdin shows up there as well.

**Where the detail lives.** The review ledgers are git-ignored and exist only on this machine, in
`.superpowers/sdd/` inside the `ecstatic-mendeleev-58a65e` and `dynamic-adrs-agents-a4a767` worktrees, under
`.claude/worktrees/`. They hold every ruling and about 80 minor ADR findings. Removing those worktrees deletes them, so
copy them out first if you want them.
